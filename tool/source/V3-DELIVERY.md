# VibecodeKit MQL5 v3.0-alpha.3 Delivery Note

## What this update does

This package composes the v5.1 cognitive workflow with the MQL5 2.6.x runtime
without mixing semantic intent, code changes and release evidence.

Alpha.3 closes the provenance gap found in the deep audit: all release-looking
paths now call one validator that checks trusted execution provenance, core
artifact hashes, real report structure and the hash chain.

### Implemented choices

| Decision | v3-alpha behavior |
| --- | --- |
| Approved `EA-SPEC` | Agent may change only derived metadata; semantic changes require a change request and owner approval. |
| Live approval | `OWNER_APPROVAL.json` must bind owner, target, build hash and evidence hash; live additionally requires a stronger identity assertion and Windows-native authority. |
| Windows/Wine | Both supported; Windows-native is release authority, Wine is development/CI. |
| ONNX | Optional plugin policy; stub models are not inference evidence. |
| Backtest | Required for behavior/risk changes and forward/live scope, not for docs-only work. |
| Broker portability | Capability/profile-first; broker-specific adapter only when a profile cannot express behavior. |
| Lite | Cannot change trading behavior; router promotes to Standard/Full. |
| Decision Ledger | `DECISIONS.yaml`, versioned with the project. |
| Evidence store | Local-first; remote is optional and must redact sensitive data. |
| MCP | Internal/experimental until schemas stabilize. |
| Guard conflict | Hard P0 wins; owner can override advisory rules; waivers require explicit scope and expiry. |
| Telemetry | Off by default; anonymous opt-in only for sanitized operational metadata. |

## Known boundaries before production

- A real authenticated owner identity provider is still needed for live approval.
- Evidence provenance is intentionally conservative: old manifests without
  producer metadata are `UNTESTABLE` and must be regenerated by a trusted run.
- Windows-native MetaEditor/MT5 and broker tests are required before live use.
- ONNX model sourcing, license, hash and action-label mapping must be completed
  before enabling the optional plugin.
- MCP remains an internal adapter, not a stable public API.
- Retro checkers are intentionally shallow and conservative; a local PASS is
  not compile, profitability, broker or live evidence.
